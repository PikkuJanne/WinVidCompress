# Process, CLI, progress and reporting

## Native adapter

Keep command construction as an argument-token array and execution as a small separate adapter. No Invoke-Expression or dynamically concatenated cmd/PowerShell expressions. Literal path APIs protect filesystem operations; native quoting still needs host-specific argv round-trip tests. .NET Framework/Windows PowerShell 5.1 do not have every API available in PowerShell 7, so verify ProcessStartInfo usage rather than importing a 7-only pattern.

Capture native exit code and stderr. Do not interpret any stderr output as automatic process failure or hide it entirely. Drain both output streams without deadlock. If supporting callbacks/asynchronous readers, clean up resources and consider runspace requirements. Noninteractive stdin/FFmpeg -nostdin must not conflict with a chosen graceful cancellation mechanism. Every bounded probe/doctor call has a timeout. The long-running encoder uses user cancellation and may report a stall without an arbitrary short kill timeout.

The .bat wrapper remains thin. Test actual incoming argv with benign filename fixtures and a recorder. Windows shell expansion, PowerShell -File binding, .bat command-line limits and native argument marshalling are separate layers; avoiding delayed expansion alone does not prove all layers correct. Do not double-evaluate arguments with CALL. Keep interactive and unattended launch modes explicit.

M1-06 implements `Invoke-EnvironmentCall` for seven dependency inspection calls, each with a 10-second process/pipe-drain deadline plus bounded failure cleanup. It uses PS5.1-compatible ProcessStartInfo.Arguments with Windows argv quoting, concurrent stdout/stderr tasks, closed stdin, checked exit codes and retained stderr. Child FFREPORT is cleared to avoid automatic log writes. Timeout cleanup stops the directly started process; detached descendants are not tracked, and inherited pipe handles cannot cause an unbounded drain. Process creation and filesystem/network resolution remain Windows API boundaries rather than promised total startup deadlines. M2-01 reuses this small helper for the single JSON media inspection with opt-in structured failure and UTF-8 output; environment-call failure behavior remains unchanged.

M2-03 uses pure `Get-EncodeArguments` tokens and `Invoke-EncodeProcess` for normal encoding. The profile, maps, height cap and filename tags are preserved; `-stdin` now enables only the private redirected pipe for a bounded quit request; the child never receives menu/console input. Raw/developer and decode calls still close stdin immediately (decode retains `-nostdin`). Windows CRT quoting uses ProcessStartInfo.Arguments on both PS5.1 and PS7. Both UTF-8 streams are drained concurrently in chunks on the calling runspace, with no PowerShell callbacks or native stderr error records. Raw adapter mode displays chunks live; managed encoding displays parsed progress. The structured result includes start/success state, nullable native exit, failure kind/error, elapsed seconds, separate stream tails, character totals and truncation flags. Capture retains at most 1048576 characters per stream; truncation is disclosed; raw adapter mode continues streaming console chunks. M3-05 adds an optional managed progress context: normal encoding parses machine stdout, suppresses raw streaming and keeps separate diagnostic tails. The raw adapter mode remains available to developer recorders and the explicit decode helper.

There is no total encoding deadline. After observed native exit, pipe draining has a 10-second bound, including inherited handles. Exceptions stop only the directly owned encoder, with a 2-second termination wait and resource disposal. Pipeline interruption propagates; an owned-process cleanup failure aborts the batch rather than scheduling another job. M3-06 adds controlled batch cancellation and a private graceful quit before the same direct-child fallback; detached descendants and console close remain outside that cleanup guarantee. M2-04 now encodes into an independently reserved, initially absent temporary MP4 and publishes using a same-volume no-clobber move. Failed/ambiguous partials are retained and reported; even an empty job is retained if encoder termination failed. Done requires native success and publication, while structural media validation remains M2-05. See OUTPUT_SAFETY.md for the exact implemented ownership and reporting boundary.

Exact applications resolve PATH first, then script-adjacent copies; shell shadows are rejected. Version identity/build output, exact libx264/AAC encoders, MP4/faststart and scale help are checked. FFprobe program-version output exercises CSV/JSON writers plus show_entries/select_streams without a media file. `-CheckEnvironment` is a non-converting, non-persisting diagnostic route, including the disclosed temporary destination write check described in CONFIG_AND_DISCOVERY.md.

## Supported filename boundary

Owner-approved D005 (2026-10-05): BAT drag/drop excludes environment-variable-shaped percent segments such as `%PATH%` anywhere in the full path. Use menu option 2/3 with a literal path or invoke the PS1 from PowerShell with single-quoted literal string arguments. Ordinary percent names remain supported. Direct Explorer percent substitution is retained as a measured limitation, not repaired behavior. Shell limits and delayed expansion in an outer CMD caller still apply.

## Optional CLI

M4-01 adds named-only -OutputDir, -CollisionMode rename|skip and -WhatIf alongside -CheckEnvironment, preserving positional file/folder paths before or after controls. M3-07 provides -Resume / -ManifestPath / -StrongSourceHash for explicit batches; -PreserveSubfolders remains future work. CRF has no public switch and remains 22. Unknown options captured by the remaining-path binder are rejected before startup; filenames beginning with a parameter dash need an absolute path or .\ prefix.

Precedence is built-in defaults < saved config < explicit per-run controls. Config retains its OutputDir-only default shape; optional CollisionMode must be rename or skip. Missing CollisionMode uses rename and unknown fields remain preserved. Resolve-RunConfiguration copies the preference object. Explicit controls and preview read config without lock/recovery/save: absent config stays absent, malformed config fails unchanged, and OutputDir can override a syntactically valid offline saved destination before availability checks. Normal no-option startup retains Load-Config recovery/persistence and the four-item TUI. Per-run conversion/preview requires explicit input; doctor permits OutputDir without input and rejects CollisionMode.

For a new resumable batch, use `./WinVidCompress.ps1 -ManifestPath 'D:\Jobs\batch.json' 'D:\Sources'`. Retry with `./WinVidCompress.ps1 -Resume -ManifestPath 'D:\Jobs\batch.json' 'D:\Sources'`. The manifest parent must exist and the first manifest file must not exist. Add `-StrongSourceHash` on creation and every resume to compare source SHA256 instead of only size/mtime. BAT unattended supports the same flags with `-Unattended` first. Manifest controls require explicit input paths and refuse menu/no-input or -CheckEnvironment combinations; they do not alter the four-item menu/config/default profile. Resume needs the exact original frozen eligible source set and current output root, and uses safe rename for retries. See [identity, scope and atomicity policy](OUTPUT_SAFETY.md#manifest-and-resume).

-WhatIf returns a separate Preview/Plans result from read-only config, directory and frozen queue inspection. It starts no native tools, calls no output-write test, and creates no config/locks/backups/directories/jobs/logs/manifests. Names account for existing paths and prior planned flat destinations using case-insensitive in-memory reservations. WouldEncode/WouldSkip are estimates, not completed jobs or savings. Media validity, destination writability, encode success and concurrent collisions remain unchecked. The output directory must already exist. Empty/unusable plans return2, partly failed scans with planned files return1, otherwise0. Preview rejects doctor or manifest controls before any read/write/native startup; preview explicit inputs without those controls. -CheckEnvironment retains its documented temporary write test and no-conversion/no-config-save behavior. Unattended calls never prompt.

```powershell
.\WinVidCompress.ps1 -Unattended -WhatIf -OutputDir 'D:\Output' 'D:\Sources'
.\WinVidCompress.ps1 -Unattended -OutputDir 'D:\Output' -CollisionMode skip 'D:\Sources'
.\WinVidCompress.ps1 -CheckEnvironment -OutputDir 'D:\Output'
Get-Help .\WinVidCompress.ps1 -Full
```

## Result and exit contract

M2-06 implements `New-JobResult`, `Compress-One`, `Get-BatchResult`, `Process-Paths`, `Get-SessionResult` and `Invoke-WinVidCompress` as result-returning helpers. Only the executable entry boundary exits. Dot-sourcing returns before startup/exit, including when switches are supplied. The optional old counter reference on Compress-One is a compatibility adapter updated from the same record; normal dispatch does not use it.

Each job has schema version 1, a unique job ID (the reservation ID once allocated), literal source path, candidate/final/temporary/retained-artifact identifiers, outcome, reason/stage, selected absolute video/audio indices, configured/applied profile settings, elapsed seconds, nullable input/output byte lengths and signed size change (output minus input). Output bytes/size change describe only a published final; an existing skipped file is never counted as produced. Unavailable sizes remain null; zero input bytes never cause percentage division. Probe/encode/validation results and cleanup warnings remain in memory, including bounded native diagnostics. LogPath is populated when a job runs in an application session with M3-05 local logging; standalone dot-sourced Compress-One calls retain null. ProgressStates records attempted encoding and subsequent states without treating preparation/probe failures as encoding. Retained.json still stores the M2-04 identity/stage/reason boundary, not the complete result or stderr.

Outcomes are Completed, Skipped, Failed, Cancelled and Unstarted. Completion requires native success, M2-05 validation and M2-04 no-clobber publication. Reporting/cleanup faults cannot relabel a published final or an intentional valid skip. A separate CancellationRequested flag can stop the batch after completion/skip while retaining that job's durable outcome. Unknown/missing/multiple/mismatched returned records fail dispatch and stop scheduling. Fatal owned-process cleanup exceptions remain failures; their attached job record is consumed by the batch, and every remaining queued source becomes Unstarted. PipelineStoppedException still propagates through owned cleanup rather than promising successful reporting in an already-stopped pipeline.

The frozen queue produces one record per unique source. Found equals Done + Skipped + Failed + Cancelled + Unstarted. Scanned counts successful input-selection scans; ScanErrors retains separate scan error records and never inflates Failed jobs. Each requested empty/invalid batch returns 2, including an empty explicit Paths array; an empty menu selection makes no batch request. Menu sessions retain earlier job records when later batch startup fails and preserve any earlier batch failure/empty-request/cancellation exit.

Application exits: **0** completed without failures, including intentional valid skips; **1** one or more job/scan failures or unstarted jobs after fatal dispatch; **2** startup/config/invalid-request/no-eligible-input failure; **3** observed explicit application cancellation. Precedence is cancellation, then startup/invalid/empty requested batch, then job/scan failures, then success. Cancellation before queueing is a batch signal, never a fabricated source job. Quit/blank menu cancellation before a requested batch returns 0. -CheckEnvironment succeeds with 0 despite having no jobs, and reports startup/doctor failure with 2.

Normal direct PS1 -File batches exit with the result's code. `-Unattended` makes an input request explicit and forbids falling into a menu; no paths returns 2 before tool/config startup. The BAT supports **first argument** `-Unattended`, forwards %* once, omits -NoExit, and never pauses (including missing-script/host errors). Default double-click/drag-drop adds PS1 -KeepOpen with -NoExit, returns to a usable PowerShell prompt and sets LASTEXITCODE to the application result; the user's later shell exit is not the unattended batch exit. Combining the switches is an invalid request (2). D005 percent-shaped and outer-CMD/length/native-quoting limits remain.

This contract covers application results, not errors before script execution. Host argument parsing/binding can return the host's own error code. Controlled cancellation/result seams exercise code3 and finalized reports. Physical Ctrl+C remains manual A01 until each launch mode is observed; console close/Ctrl+Break/crash and detached descendants remain outside controlled cancellation. Microsoft documents -File exits and notes that Ctrl+C can return 0: [Windows PowerShell host](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_powershell_exe?view=powershell-7.4), [PowerShell 7 host](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_pwsh?view=powershell-7.6). No physical cancellation acceptance follows from the controlled seam.

## Progress/logs

Use FFmpeg machine progress key/value records, not human stderr scraping. Handle partial records, unavailable numeric values and differing timestamp fields. Show file index/total, current state, elapsed and approximate remaining time. Unknown duration produces indeterminate progress; do not divide by zero or invent an ETA. Distinguish encoding, finalizing (including container work), validating and complete.

Keep a concise console view and persistent bounded local text/JSON reports. Record actual versions and settings. Log-write failure must be visible but cannot justify deleting a good final output; define its warning/batch-failure policy consistently. Never upload logs. Provide redacted sharing that removes user-specific roots and filenames/metadata as selected, and document what remains. Test redaction against nested paths, non-ASCII names and FFmpeg diagnostics.

### Implemented M3-05 progress and local logs

Encoder tokens now include `-nostats -progress pipe:1`; the [FFmpeg progress contract](https://ffmpeg.org/ffmpeg.html#Advanced-options) supplies key/value records terminated by `progress=continue` or `progress=end`. The caller runspace handles fragmented UTF-8 chunks/CRLF/final lines without asynchronous PowerShell callbacks. Unfinished lines are limited to 4096 characters, only four known fields are retained, malformed/N/A/nonfinite/negative values are tolerated, and numeric parsing is invariant. Timestamp preference is out_time_us, historical microsecond-valued out_time_ms, then out_time. Regressing positions cannot regress the percentage. Unknown/nonpositive duration is indeterminate; known duration stays below 100 until structural validation and no-clobber publication. Remaining time is an approximate encode estimate from positive speed, excluding validation/publication. Elapsed includes preparation. File index/total reflects the frozen unique queue.

Encoding, Finalizing, Validating, Publishing and Completed states are recorded. End means native encoding/muxing is ending, never application completion. FFmpeg does not identify the exact beginning of faststart/container work in this stream; Finalizing covers the end/exit boundary, not an independently measured faststart phase. Native success without an end marker still transitions to Finalizing before validation. Ordinary failures show a bounded stderr tail and retain the fuller local diagnostic tail. Progress display cancellation follows the existing result/stop-scheduling rules; this is no new physical Ctrl+C guarantee.

After successful normal startup, each invocation creates a GUID session under `%APPDATA%\WinVidCompress\logs`, with `session.txt` and `results.jsonl`. Doctor and startup failures before session creation do not write logs. JSONL contains schema-version-1 Session, Job and Result records; completed job records are appended before scheduling the next job, including skips/failures/unstarted jobs. Session identity, actual application SHA256, PowerShell/native build versions, literal encoder tokens, applied settings, selected streams, stage/outcome, timing/size results and bounded native tails are projected without copying source probe/tag trees. Ordinary session completion records exit/counters and up to 20 scan errors; controlled batch cancellation appends cancelled/unstarted jobs and the final result; forced host/pipeline/console/crash interruption can still leave partial logs.

Each file is capped at 1 MiB including a reserved truncation marker; reaching either file's limit marks both reports and omits later records. Each diagnostic tail retains at most 8192 characters plus its truncation label; native character/truncation fields remain. A hard 128-session directory quota bounds owned logs to at most 256 MiB plus filesystem overhead. A shared exclusive quota.lock handle serializes local session admission; contention follows the visible warning-only policy. Old logs are never removed automatically. Manually remove reviewed session directories to resume logging at the quota. File creation uses CreateNew; existing files are never overwritten. Log availability/write/limit failures produce one visible warning per session, propagate to the session result, and leave compression outcomes and exit status unchanged. Logs are private local records: they include source/output paths, filenames, metadata tokens and diagnostics. None are uploaded.

Explicit sharing export from a PowerShell shell:

```powershell
. .\WinVidCompress.ps1
Export-WvcDiagnostic -SessionPath 'C:\local\session\results.jsonl' -DestinationPath 'C:\local\share.json'
```

The destination must be absent. Default export removes all structured paths, input/output argument paths, filenames/stems and metadata values, omits free-form errors/warnings/scan errors/stdout/stderr (which may contain unknown inherited private tags), and retains only version identity tokens from build text. IDs, outcomes, settings, native failure kind/exit code, diagnostic counts/truncation and measurements remain. `-Roots @('D:\additional-private-root')` supplies additional values to redact. `-RedactMetadata $false` explicitly retains reviewed diagnostic/metadata text with path/filename replacement; unknown personal text can remain and must be reviewed before sharing. `-RedactFilenames $false` permits names in explicitly retained metadata/text while absolute structured paths stay redacted. There is no automatic export, telemetry, upload, network call or config change. This helper is a local diagnostic route, not a new executable CLI switch.

## Cancellation

M3-06 owns `Console.TreatControlCAsInput` only for a requested batch and restores its prior value in finally. The caller runspace polls at most 32 available keys per cycle; Ctrl+C latches a request, and other typed keys during the batch are consumed without forwarding to FFmpeg. There are no PowerShell/native event callbacks. Redirected or unavailable console input keeps host interruption behavior; later console loss disables polling with a visible warning and cannot bypass owned cleanup. Ctrl+Break, console close, host pipeline interruption, hard crash and power loss remain distinct unsupported controlled paths. [Microsoft keyboard input contract](https://learn.microsoft.com/en-us/dotnet/api/system.console.readkey), [Ctrl+C input mode](https://learn.microsoft.com/en-us/dotnet/api/system.console.treatcontrolcasinput).

Managed encoding keeps private redirected stdin open and uses `-stdin`. On a request the runner asynchronously sends the fixed `q` plus newline once, continues draining stdout/stderr for up to 1500 ms, then calls Kill only on its directly owned Process with a 2000 ms termination wait. Raw/developer and explicit decode calls retain closed stdin. It never forwards menu input, broadcasts console events, runs taskkill or terminates by process name. Detached descendants of arbitrary replacement executables are not tracked; the ordinary FFmpeg child is directly owned. Existing post-exit pipe drain is capped at 10 seconds, so inherited handles can delay final reporting. [FFmpeg stdin option](https://ffmpeg.org/ffmpeg.html#Main-options), [official Windows pipe/q implementation](https://github.com/FFmpeg/FFmpeg/blob/master/fftools/ffmpeg.c).

Native cancellation metadata records Requested, GracefulAttempted, ExitedDuringGrace and Forced. ExitedDuringGrace means the child exited after the quit attempt without forced termination; it is not an acknowledgement that q caused the exit. Tests separately require actual installed FFmpeg's q acknowledgement. Native exit 0 after q is still application cancellation, never native application success. Cancellation is checked before native launch, after encode, before allocation/publication, after validation/display and between frozen queued jobs. Already published Completed and valid Skipped records keep those outcomes and carry CancellationRequested; remaining sources are Unstarted. Found still reconciles, cancellation wins exit precedence (3), and logs project the cancellation signal/stop fields and session Cancelled state. A late request during summary records session code3 even when no job outcome is Cancelled. Bounded probe/validation and filesystem calls can delay key observation; cancellation does not interrupt a native filesystem operation midway. A request observed after a completed no-clobber move keeps that output.

Termination failure aborts scheduling and retains job provenance even if no partial exists. Failed/cancelled partials remain unverified under the existing owned-output policy and are never promoted. Context and console restoration failures cannot replace completed batch results. Physical A01 requires the prepared Windows checks in tests/README.md; automated context/native seams are not that observation. Controlled cancellation finalizes ordinary reports subject to the existing warning-only log admission/size/write policy. Crash-only leftover directories may lack retained.json and remain unverified on subsequent inspection.
