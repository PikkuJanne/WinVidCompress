# Media inspection, selection and encoding contract

These are proposed implementation requirements derived from the agreed review. Consult the current FFmpeg/FFprobe documentation and verify behaviour with pinned tool builds. Do not treat a suggested filter expression as already tested.

## Normalized probe result

Use a bounded native probe with captured stderr/exit code and JSON parsing. Return an object with input identity, all stream indices/types/dispositions, selected real video/audio indices, coded and display geometry, rotation/display matrix, SAR/DAR, pixel format, colour primaries/transfer/matrix, frame-rate information, audio channels/sample rate and source duration where known. Store unknown values explicitly. Reject malformed responses, probe failures and no-real-video inputs before encoding.

Do not infer duration from filename or file size. Duration can be absent/uncertain; progress becomes indeterminate and duration-validation limitations must be reported. Bounded retries, when justified, must not mask corrupt media. Inputs are user-selected files, not URLs or scripts; reject playlists/unsupported protocol-style inputs and review FFmpeg protocol/demuxer restrictions against actual supported containers. Never promise an absolute offline guarantee without verifying all process paths.

M2-01 implements `Get-MediaInspection` and the pure `ConvertFrom-ProbeJson` normalizer. Each input gets one UTF-8 JSON `-show_streams -show_format` call with a 10-second process/pipe deadline, retained native status/stdout/stderr and structured source/probe/JSON/validation failure. Source selection requires an existing literal filesystem file with a supported video extension. The probe allows only the `file` protocol and rejects hls/dash/concat format responses. These checks do not establish an absolute offline guarantee: UNC file access and the existing encoder path retain their separate boundaries.

The normalized schema preserves all stream indices/types/dispositions, coded width/height, display matrix or rotation tag, SAR/DAR, nullable pixel/colour/frame-rate/time-base values and audio channels/sample rate/layout/language. Streams are ordered by absolute index; attached pictures are excluded from real-video candidates. A real video requires a codec and positive integer coded dimensions. Optional absent/unusable values remain null. Duration prefers a positive finite format value, then the first real video's duration; missing/invalid values carry explicit Unknown/Invalid state, indeterminate progress and the unavailable-duration-comparison warning/limitation. Parsing uses invariant culture and tolerates extra fields.

Compression refuses inspection failures. M2-02 carries the first real video's object and absolute index into the stream plan and explicit mapping. The raw probe retains `GeometryState=MetadataOnly` and null DisplayGeometry; M3-01 derives the selected-stream `Get-StreamPlan.Geometry` separately without mutating inspection. M2-04 supplies owned temporary publication, and M2-05 validates that temporary MP4 before promotion. Optional normalized frame count, codec tag and stream/global timecode support output checks without changing input selection. See [output validation and duration policy](OUTPUT_SAFETY.md). Unknown source duration discloses unavailable comparisons; structural checks still run. Structured progress remains later work.

## Stream contract

Select the first real video stream by index for the documented first-video behaviour, excluding attached pictures. Probe this same selected stream's fields and explicitly map its absolute index in the encode. Select uniquely default-disposition audio when available, otherwise the first audio; log the selection and warn about alternatives omitted. No audio is a valid input case.

Do not silently add audio, downmix channels, force FPS, or preserve arbitrary subtitle/data/attachment streams. Subtitles remain out of scope and omitted streams are disclosed. Language/disposition metadata should be retained deliberately where relevant. Any owner preference for another audio policy belongs in DECISIONS.md before changing the default again.

M2-02 implements the pure `Get-StreamPlan` and `Write-StreamPlan` console report. The plan carries the inspection's existing PrimaryVideo object/index, selects exactly one unique-default audio stream or otherwise the lowest audio index (including ambiguous multiple defaults), and records every omitted index/type/reason. No audio yields a null audio selection. Selected channels/layout/sample rate/language/disposition flags remain the normalized values; absent values are reported as unknown. Explicit unknown stream types remain identifiable and are omitted rather than rejected as missing metadata.

The same plan supplies `-map 0:<absolute-video-index>` and, when present, `-map 0:<absolute-audio-index>`; height-cap decisions use the selected video's oriented raster geometry. There are no optional maps, channel/sample-rate/FPS overrides, synthetic audio or complex filters. AAC 160k options are emitted only with selected audio; libx264/veryfast/CRF22/faststart remain. Selected stream metadata/dispositions use FFmpeg's default mapped-stream copying, with no clearing/forced-default override. Recorder argv alone does not establish output identity or playback integrity; installed-tool evidence is recorded by task and build.

## Geometry

Keep no crop/no upscaling and the existing height-cap product policy, not a new width-bounded preset. Compute based on display geometry and selected stream. Account for FFmpeg autorotation exactly once; test rotation metadata handling and output orientation. Preserve display aspect ratio, handling non-square pixels intentionally. Ensure encoder-compatible even dimensions with bounded rounding; do not add a generic crop or upscale a small clip to make dimensions convenient.

Required cases: small/SD source, 1080p, 4K, portrait, 90/180/270 rotation, ultrawide, anamorphic SAR and odd width/height. Confirm output geometry by probe and visual test patterns, not only command string inspection. VFR and high-frame-rate input must not receive a hidden frame-rate conversion policy.

M3-01 keeps FFmpeg's default autorotation, which runs before the user scale filter. It adds no manual transpose/rotate or rotation override. Quarter turns swap coded width/height and invert SAR; half turns retain both dimensions. The height cap applies to vertical raster rows after orientation, not a 1920-wide bounding box or a conversion to square pixels. A 3440x1440 source becomes 2580x1080; an already even 2560x720 source stays 2560x720. [Autorotation options](https://ffmpeg.org/ffmpeg.html#Video-Options), [transpose SAR implementation](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n7.1/libavfilter/vf_transpose.c).

For oriented W/H, target H is the largest even integer no greater than min(H,1080). Target W is W*targetH/H rounded to the nearest even integer (ties away from zero), clamped to the largest even integer no greater than W. Dimensions below 2x2 fail with an actionable reason instead of enlargement. Already even uncapped input gets no filter; other input gets the literal `scale=<targetW>:<targetH>`. Odd inputs are resampled rather than cropped: 641x479 becomes 640x478, and 640x479 becomes 638x478. Normal nearest-even width rounding differs by at most one pixel; the no-enlargement clamp can reduce an odd width by one pixel. Portrait 1080x1920 retains the established nearest-even 608x1080 result.

Scale adjusts output SAR to retain display aspect despite integer raster rounding. No `setsar=1` is applied: 608x1080 portrait output may have slightly non-square pixels. Known SAR determines oriented display aspect; source DAR, when also known, must agree within 0.1 percent. Output dimensions must match the exact plan, and output display aspect from width/height/SAR must agree within 0.1 percent relative error, allowing encoded rational approximation. Unknown SAR is disclosed; no square-pixel certainty or completed aspect comparison is fabricated. [Scale SAR calculation](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n7.1/libavfilter/vf_scale.c).

Supplied display matrices remain authoritative even if their optional text/angle is malformed. Only exact canonical signed-permutation matrices (quarter turns/axis reflections), with no scale, skew or perspective, are supported. Translation must be zero or the exact full-frame origin rebase. Duplicate, incomplete, contradictory or arbitrary transforms fail before output allocation; arbitrary-angle rotation could clip corners with FFmpeg's default canvas. Output must have no display matrix or a strict identity matrix and zero rotation, preventing a second player transform. Metadata checks do not prove full decoded or visual integrity. [Matrix representation](https://raw.githubusercontent.com/FFmpeg/FFmpeg/n7.1/libavutil/display.h).

The plan remains a snapshot for reporting; encoding and validation derive geometry from the same selected Video reference. Geometry tests exercise literal generated filters, physical decoded quadrant orientation with output autorotation disabled, SAR read-back, unchanged source/final sentinels, and HFR/VFR frame timestamps on the recorded installed build. The application adds no `-r`, FPS filter, `-vsync` or `-fps_mode` override. Compatibility and preservation claims are bounded to executed fixtures/builds; owner sample viewing remains separate.

## Colour

Establish tested SDR yuv420p output compatibility. Use transfer/colour evidence to recognize PQ/HLG HDR; bit depth alone is insufficient. For a known HDR path not deliberately supported, return an actionable unsupported result without silent washed-out conversion. Do not merely change colour tags to claim SDR. Ambiguous colour metadata warrants explicit warning/limitations rather than fabricated certainty.

Tone mapping is outside the initial implementation. Any later path needs separate colour transforms, tests and owner review. Keep accepted quality settings unless the owner authorizes a measured change.

M3-02 adds a selected-stream colour plan without changing libx264/veryfast/CRF22/AAC160k or geometry. Output explicitly requests 8-bit `yuv420p`; higher depth/chroma are reduced and disclosed. PQ (`smpte2084`), HLG (`arib-std-b67`) or surfaced mastering/content-light/Dolby Vision/dynamic HDR metadata produce an actionable `Failed` job at Colour before allocating any output. Bit depth and BT2020 primaries/matrix alone do not establish HDR. No tone mapper or HDR-to-SDR tag substitution is used. [FFmpeg pixel-format options](https://ffmpeg.org/ffmpeg.html#Advanced-Video-options), [transfer characteristics](https://raw.githubusercontent.com/FFmpeg/FFmpeg/master/libavutil/pixfmt.h).

Known conventional YUV SDR primaries, transfer and matrix tags are retained as literal encoder options, including BT709, SMPTE170M and nonconstant BT2020 SDR. Wide gamut is disclosed; this does not convert to Rec709 or promise every player supports it. Missing/unrecognized colour fields warn that HDR absence and fidelity cannot be established; missing Rec709 tags are not invented. Explicit RGB, linear/log/V-log, constant-luminance/ICTCP/specialized matrices and contradictory full-range pixel/limited-range tags are unsupported pending validated conversion work. This is a bounded compatibility path, not a general colour-management system.

Full-range YUV SDR (`pc`, or legacy `yuvj*` without contradicting tags) uses actual `scale` sample rescaling from full to limited range. Options append to the exact geometry scale, or use `scale=iw:ih` when dimensions already match. Output signals `tv`; ordinary limited or unknown-range YUV retains FFmpeg's range behavior. Output validation requires exact `yuv420p`, rejects HDR/specialized output and checks every planned known colour tag. Only otherwise wholly untagged H264 may omit limited-range signalling with an explicit validation warning; this exception does not apply to tagged SDR. [Scale range options](https://ffmpeg.org/ffmpeg-filters.html#scale), [libx264 VUI implementation](https://raw.githubusercontent.com/FFmpeg/FFmpeg/master/libavcodec/libx264.c).

Synthetic native tests verify decoded luma endpoints/neutral chroma, colour patches, tag read-back, unchanged source/final sentinels and no HDR output allocation on the recorded installed build. Their deliberately tagged fixtures do not establish authentic HDR playback/conversion. Stream-level probing cannot prove every per-frame colour/HDR change is surfaced. Structural checks and rendered stills do not establish general visual/audio integrity or display calibration. Owner reviewed four source/output pairs and approved this tested SDR default under D006 on 2026-10-06; no milestone/release acceptance follows from these checks.

## Filename metadata

Retain the three existing date formats and title fallback. Use culture-independent real-date parsing; test leap years, impossible dates, extra/multiple date tokens, missing artist and the eight-digit fallback. Never fabricate a date when parsing is ambiguous. Compression continues if tags cannot be parsed. Unicode text and shell-looking punctuation remain data, never executable syntax.

Define tag precedence: generated filename title and valid interview artist/date/comment intentionally override those fields; preserve other compatible source tags only by documented policy. Document privacy implications and prove selected tag read-back with FFprobe on the packaged dependency baseline. Do not copy unrelated private tags blindly while claiming the output contains only four fields.
