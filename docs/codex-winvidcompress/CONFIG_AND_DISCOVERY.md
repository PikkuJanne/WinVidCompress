# Configuration and input discovery specification

## Configuration

Continue to understand the existing `%APPDATA%\WinVidCompress\config.json` with `{ "OutputDir": "..." }`. Inject config/output roots into tests; never test against the actual user profile. Validate JSON root, property presence/type and path semantics before strict property access. Unknown keys should survive a compatible save where possible.

A missing config may use the Windows known Videos folder on a normal first run. A malformed config may be preserved under a collision-safe diagnostic backup and replaced with explicit defaults, with an explanatory message. If the known-folder path is empty or unusable, fail clearly; do not choose an arbitrary root. An offline destination/permission failure is not malformed JSON. Do not overwrite the saved destination or quietly put videos somewhere else.

Use owned temporary writes and tested atomic replace/no-clobber primitives; retain a last valid file on failure. Protect simultaneous writers or diagnose conflict. Do not claim all network filesystems provide identical atomicity. `-WhatIf` and `-CheckEnvironment` do not create config, directories or backups.

M1-03 implements object-root/type validation and absolute drive/UNC path syntax checks. A usable known Videos directory is required for first-run defaults or malformed recovery. Recovery preserves exact original bytes in `config.invalid-<unique>.json` and prints the reason and backup location. A valid saved directory that is missing, offline, a file, or inaccessible stops startup without changing the saved destination. Configuration validation checks directory access without creating output.

M1-06 adds a distinct destination write check at startup, before saving a menu output selection, and at each batch boundary: GUID-named CreateNew temporary file, one-byte write/flush, DeleteOnClose. Existing source/final/config files are untouched. `-CheckEnvironment` uses read-only config parsing (or unsaved Videos defaults), refuses malformed preferences without recovery, and reports exact PATH-before-adjacent applications/builds/capabilities. The doctor creates no config, directories or backups; its only filesystem write is the disclosed owned temporary check inside the existing destination. Capacity is current/advisory, unknown on UNC/reparse/mount-point paths, with a warning below 1 GiB and no size guarantee. These snapshots cannot ensure later permission/capacity stability or bound Windows filesystem/network calls.

Saves use an exclusive `config.json.lock` sidecar, a byte-exact loaded snapshot, an owned sibling CreateNew temporary file, a no-clobber `config.previous-<unique>.json` backup, and File.Replace (existing) or no-clobber File.Move (first run). The empty lock sidecar remains to avoid lock-deletion races. Backups are retained; no automatic pruning. A stale session must restart/reload before saving. The menu saves a copied config before changing its active preference. These primitives coordinate participating instances; external editors that ignore the lock can still race, and network filesystem/crash durability is not guaranteed by the local Windows checks.

Unknown compatible keys survive deep serialization without a schema reset. Objects/arrays beyond JSON depth 100 are refused before writing, including on PS5.1 where the serializer otherwise silently truncates. Hosts exposing ConvertFrom-Json DateKind use String to retain timestamp strings; older PowerShell 7 hosts can normalize ISO timestamp formatting through their standard DateTime conversion. PS5.1 and tested PS7.6.5 preserve the tested unknown timestamp string exactly. Preview/environment flags are later CLI scope; M1-03 does not introduce them.

## Selection/discovery

Resolve existing filesystem sources with literal semantics. Reject web URLs and unsupported filesystem-provider inputs; UNC sources may be supported as explicit user-selected network files, not as an upload service. Source-folder selection never creates missing folders. Output-folder creation requires actual output selection/run intent and is disabled under WhatIf.

Keep the existing extension list as the baseline. An extension is only a candidate filter, not proof that the content is video. Explicit files need the same supported-media/preflight policy as discovered files. Adding extensions is a deliberate tested change, not a generic accept-anything bypass.

Normalize results into arrays; expose inaccessible subtrees and invalid selections as scan errors. Establish a reparse-point policy before recursion; do not follow junction loops or silently traverse out of selected roots. Case-insensitive normalized Windows path identity is the default deduplication key; document that alternate filesystem identities/hard links need additional evidence.

M1-04 implements `Get-InputScan` with `InputPath`, `NormalizedPath`, `Files[]`, `Errors[]` and `Succeeded`. Existing filesystem selections resolve literally to FileSystemInfo.FullName, including relative/dot-segment and filesystem PSDrive paths. Non-filesystem providers, blank/missing paths and unsupported explicit file extensions produce records containing Path, Kind and the original diagnostic message. The existing extension list applies case-insensitively to explicit and discovered files; extensions are still only candidate filters. A read-only open with shared read/write/delete access checks current file readability without reading content. Discovery does not establish media validity or guarantee later access.

Traversal uses a nonrecursive literal enumeration and an explicit stack. All encountered reparse points (directory junctions, symbolic links, reparse files), explicit reparse roots and selections beneath reparse ancestors are excluded and reported. Select the physical target directly when intended. An ordinal case-insensitive visited-directory set refuses repeated traversal as a second cycle guard. Hidden/system enumeration remains the previous Get-ChildItem default. Reparse checks are path-based, with a race between checking and listing/opening; this is a conservative stable-filesystem policy, not an atomic boundary against concurrent malicious filesystem replacement.

Listing/access errors retain readable siblings and mark the scan incomplete. Process-Paths prints every record, counts only complete selections as Scanned, and adds a separate Scan errors total. No videos found is printed only for a complete empty scan. Encoding remains sequential with the existing Found/Done/Skipped/Failed counters. Collect-InputFiles remains a file-only compatibility stream; diagnostic-aware callers use Get-InputScan and materialize Files arrays. Exit-code/result-model expansion is later CLI scope.

Collect the entire queue once, deduplicate and sort, then encode sequentially. Resolve intended output paths before/at job boundaries with race-safe final promotion. Inputs changing during a run must be detected (at least size/mtime before/after); report/retry rather than present a result as a faithful copy of a moving input.

M1-05 implements `Get-InputQueue` with `Files[]` and the original `Scans[]`. All selections finish before the first encode. Windows provider normalization supplies long-path-compatible keys; an ordinal case-insensitive dictionary merges repeated, overlapping, case/relative/dot/PSDrive/provider and ordinary extended drive/UNC aliases. Special extended literals ending in dots/spaces remain distinct. Ordinal key sorting and a stable ordinal-minimum invocation spelling make queue order independent of selection order and culture. Found counts unique queued paths; Scanned and Scan errors retain selection-level completeness and every diagnostic appears before encoding. Empty Files/Scans remain arrays.

This freezes candidate paths, not media bytes or filesystem IDs. Different hard-link, 8.3, mapped-drive/UNC or other filesystem-identity aliases may remain separate jobs. Size/mtime change detection, owned temporary transactions and trusted manifests remain later pipeline/resume work; this task does not establish faithful output from a concurrently changing input or race-safe final promotion. `Compress-One` explicitly compares normalized input/output keys before probing/encoding, applies the existing rename/skip collision policy on equality and refuses any still-identical renamed path. The existing FFmpeg `-n` remains in force.

## Destination overlap and layout

Do not exclude all MP4 files, all files containing `(compressed)`, or every original inside OutputDir. Snapshotting prevents same-run output re-ingestion. Across runs, only a trusted ownership manifest or specifically managed job-temporary area can prove a generated output; ambiguous files remain visible, never silently deleted.

The current application creates no ownership manifest or owned media-temporary area. M1-05 therefore has no proven pre-existing generated artifacts to exclude. All ambiguous existing supported files remain candidates, including destination MP4s and `(compressed)`/`.partial` filenames. Files created after the snapshot cannot join that batch. Exclusion of artifacts with actual ownership proof must accompany M2-04 temporary transactions/M3-07 manifests; filename or destination heuristics cannot supply that proof.

Preserve flat output by default. An opt-in relative layout must define stable root mapping for multiple inputs and repeated root names. Derived paths must stay beneath the destination root; forbid rooted relative names, traversal and reparse escapes. If input equals the nominal final destination, choose a safe new output or skip by policy—never overwrite it.
